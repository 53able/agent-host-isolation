# Strict-memory dispatch gate

The automatic path is deliberately narrow: a trusted host controller receives a `strict-memory` `InspectBlocked` event, validates a new Apple Container `guest-build` manifest and attempt, rechecks the source snapshot bytes, runs live resource probes, and only then executes the target `task.command`. The guest gets no network or credential broker. Artifacts pass through a private staging directory and the result gate after the guest and its resources have stopped and been removed.

`scripts/guest_build_runner.py` provides the bounded command path. It creates a read-only container with fixed-size tmpfs mounts for scratch and output, a 1 MiB `/dev/shm`, and a fixed root-owned idle process. It executes `task.command` as UID 1000 with hard process and open-file limits, checks that no task processes remain, and exports output while the container is still running. The host watchdog bounds command wall time and logs; ownership-checked cleanup precedes the result-gate import. The current supported profile caps wall time at 30 seconds, logs at 1 MiB, and imported artifacts at 32 MiB. A failed command, failed exporter, failed cleanup, or rejected artifact cannot produce a successful import.

`scripts/verify_strict_memory_dispatch.py` exercises the exact runner on the local Apple Container host. It probes a normal `task.command` and result-gate import, wall and log watchdogs, process limits, disk limits on scratch, output, and shared memory, rejection of symlink, unexpected, and oversized artifacts, rejection of output from a failed task or a task with live children, and cleanup. It combines this with a fresh memory-OOM probe. The remaining seven adversarial classes and other resource limits stay `unverified` until exercised. `scripts/strict_memory_dispatch.py` runs those checks again before each attempted automatic dispatch, requires a private event record issued by the JustBash host controller, compares the target image and resource profile with the tested profile, and refuses incomplete or failed checks. It claims the target attempt durably, serializes automatic runs through one VM slot, and writes a private audit record. Imported files are placed under `/var/tmp/agent-host-isolation/imports/<task-id>/<attempt-id>`.

The earlier named-volume/root path failed enforcement on Apple Container 1.2.2: a root guest with `nproc=32` spawned 40 processes, and a volume requested at 16 MiB accepted 40 MiB. The compiler now rejects this path for ordinary strict-memory tasks; `create-probe` remains an explicit diagnostic entry for the memory OOM experiment. The supervised tmpfs/non-root path passes the process and disk denial probes on that host. Automatic dispatch remains **blocked** because the seven adversarial classes and CPU, open-file, and VM-count limits have not yet been verified through the exact path. The manual escalation request remains available.

The runner handles `task.command` as the full path selected for this profile. It is not a general agent orchestrator, network gateway, credential broker, or proof of isolation for another image, host, runtime version, or resource profile.
