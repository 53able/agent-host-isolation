# Strict-memory dispatch gate

The automatic path is deliberately narrow: a trusted host controller receives a `strict-memory` `InspectBlocked` event, validates a new Apple Container `guest-build` manifest and attempt, rechecks the source snapshot bytes, runs live resource probes, and only then executes the target `task.command`. The guest gets no network or credential broker. Artifacts pass through a private staging directory and the result gate after the guest and its resources have stopped and been removed.

`scripts/guest_build_runner.py` provides the bounded command path. It creates a read-only container with fixed-size tmpfs mounts for scratch and output, a 1 MiB `/dev/shm`, and a fixed root-owned idle process. It executes `task.command` as UID 1000 with hard process and open-file limits, checks that no task processes remain, and exports output while the container is still running. The host watchdog bounds command wall time and logs; ownership-checked cleanup precedes the result-gate import. The current supported profile caps wall time at 30 seconds, logs at 1 MiB, and imported artifacts at 32 MiB. A failed command, failed exporter, failed cleanup, or rejected artifact cannot produce a successful import.

`scripts/verify_strict_memory_dispatch.py` exercises the exact runner on the local Apple Container host. It probes `task.command` through result-gate import, wall and log watchdogs, process and open-file limits, CPU and VM count, disk limits on scratch, output, and shared memory, the seven adversarial classes, rejected artifacts, quiescence, and cleanup. It combines this with a fresh memory-OOM probe. `scripts/strict_memory_dispatch.py` runs those checks again before each attempted automatic dispatch, requires a private event record issued by the JustBash host controller, compares the target image and resource profile with the tested profile, and refuses incomplete or failed checks. It claims the target attempt durably, serializes automatic runs through one VM slot, and writes a private audit record. Imported files are placed under `/var/tmp/agent-host-isolation/imports/<task-id>/<attempt-id>`.

The earlier named-volume/root path failed enforcement on Apple Container 1.2.2: a root guest with `nproc=32` spawned 40 processes, and a volume requested at 16 MiB accepted 40 MiB. The compiler now rejects this path for ordinary strict-memory tasks; `create-probe` remains an explicit diagnostic entry for the memory OOM experiment. The supervised tmpfs/non-root path passes those denial probes on that host. Configure a validated `strictMemoryTargetManifest` when creating the JustBash inspect runtime; a subsequent host-controller call to `blockInspectForStrictMemory` then runs the guarded dispatch automatically and records its result for `strictMemoryDispatchResult`. Without a configured target, the event remains a manual escalation request. `scripts/verify_strict_memory_auto.py` exercises this event-to-import path on the recorded host.

The runner handles `task.command` as the full path selected for this profile. It is not a general agent orchestrator, network gateway, credential broker, or proof of isolation for another image, host, runtime version, or resource profile.
